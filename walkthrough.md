# Итоговый отчет и руководство: kwork-guard v1.0.0

## 1. Анализ проблемы на вашем скриншоте

На присланном скриншоте видно:
- **Запрос:** *«Используй MCP, подключись к проекту Для_тестов и покажи, какие справочники сейчас есть в конфигурации»*
- **Расход:** **$0.23** уже потрачено на простейшую задачу!
- **Действие Roo Code:**
  ```json
  modify_metadata:
  {
    "projectName": "Для_тестов",
    "fqn": "Document.ЗаявкаКлиента.Attribute.Клиент",
    "properties": [
      {}
    ]
  }
  ```
  И затем в обдумывании модель пытается вызвать **тот же самый ошибочный метод с пустыми свойствами повторно**!

### Почему это произошло?
1. **Избыток инструментов:** В базовом подключении Roo Code видит все **55 инструментов** EDT-MCP. Модель путается в описаниях объемом более 25k символов.
2. **Отсутствие валидации:** EDT отклонил вызов с пустыми `properties: [{}]`, вернув невнятную внутреннюю ошибку Java. Модель не поняла, что пошло не так, и пошла на второй круг.
3. **Отсутствие антицикла:** Без прокси агент шлет один и тот же невалидный запрос бесконечно, сжигая баланс.
4. **Неправильный режим:** Для вопроса на чтение справочников модель вообще не должна была иметь доступ к инструменту модификации метаданных `modify_metadata`!

## 2. Что делает `kwork-guard` и как решена проблема

С разработанным комплексом **kwork-guard**:
1. **Локальный отбойник (Prevalidation):** При попытке передать пустой `properties: [{}]` прокси **не пускает запрос в EDT**, не тратит время и возвращает модели конкретный пример:
   `modify_metadata: в properties[0] нет name/value. Свойства: [{"name":"Synonym","value":"Текст"}]`
2. **Антицикл (LoopGuard):** Если вызов с одинаковыми параметрами падает 2 раза подряд, прокси намертво блокирует его с требованием сменить тактику или спросить человека. 5 любых ошибок подряд — принудительный СТОП.
3. **Узкие профили:** В режиме чтения/отчетов инструмент `modify_metadata` либо отсутствует, либо жестко контролируется.
4. **Макросы:** Вместо 8–12 последовательных вызовов создание печатной формы или отчета делается за **1 вызов** (`scaffold_vpf` / `scaffold_report`), экономя до **90% токенов**.

## 5. Инструкция по запуску для работы

1. **Запустите прокси:**
   Дважды кликните `C:\Users\timur\kwork-guard\start_guard.bat` (прокси слушает `127.0.0.1:8766`).
2. **Создайте папку для заказа Kwork:**
   В командной строке выполните:
   ```cmd
   cd C:\Users\timur\kwork-guard
   new_order.bat vpf "C:\Orders\Заказ 63984035 Печать чека"
   ```
3. **Откройте папку заказа в VS Code:**
   Roo Code автоматически подключится через `kwork-guard` к EDT, используя защищенный профиль и макросы.
4. **После завершения проверьте стоимость:**
   ```cmd
   python tools/cost_report.py --order-id 63984035
   ```
