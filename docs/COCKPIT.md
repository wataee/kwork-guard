# Kwork Cockpit 2.0 (Zero-Defect Edition)

Десктопное приложение для управления заказами 1С на Kwork, интегрированное с шлюзом-прокси **Guard 2.0**, Roo Code и 1C:Enterprise Development Tools (EDT).

## Установка и запуск

### Автоматическая установка в 1 клик
Запустите файл `install_cockpit.bat`. Он выполнит:
1. Проверку и установку Python-зависимостей из `requirements.txt`.
2. Генерацию многослойной иконки `assets/cockpit.ico` (16, 32, 48, 256 px).
3. Создание ярлыка `Kwork Cockpit.lnk` на Рабочем столе Windows.
4. Диагностику и подготовку рабочего места (`prepare_workplace()`), автоматическую проверку и восстановление `.roo/mcp.json` во всех существующих заказах.

### Ручной запуск
- Через ярлык на Рабочем столе: `Kwork Cockpit.lnk`
- Через Python без консольного окна: `pythonw launch_cockpit.pyw`
- Через консоль: `python launch_cockpit.pyw`

## Ключевые возможности

### 1. Единая панель статуса (Top Bar)
- Мониторинг состояния 1C:EDT MCP (порт 8765) и Guard (порт 8766).
- Кнопка **«▶ Подготовить рабочее место»**: запускает Guard в фоне, проверяет базу данных и заказы.
- Управление процессами: Запуск, Остановка, Перезапуск Guard.

### 2. Экран «📅 Сегодня»
- Сводные показатели: активные заказы, сумма в пайплайне, отработанные часы, текущая маржинальность.
- Секция умных алертов: горящие дедлайны, заказы с исчерпанным лимитом вызовов (>20 вызовов).
- Карточки активных заказов с быстрыми действиями: «В VS Code», «Промпт в буфер», «Карточка».

### 3. Реестр заказов и быстрый интейк
- Таблица всех заказов с фильтрацией по этапу (`lead`, `in_progress`, `review`, `delivered`, `warranty`, `archive`) и типу (`vpf`, `report`, `processor`, `extension`, `tz`).
- Поиск по клиенту, номеру и названию (`Ctrl+K`).
- Вкладка «➕ Новый заказ»: мгновенное распознавание параметров ТЗ из переписки Kwork (Regex + AI fallback), генерация структуры заказа, репозитория Git и конфигурации `.roo/mcp.json`.

### 4. Карточка заказа (6 вкладок)
1. **Обзор:** управление этапами разработки, трекинг часов (+0.5ч, +1.0ч), дедлайн, заметки.
2. **Разработка:** переход в VS Code, генерация промпта для Roo Code, встроенный синтаксический анализатор BSL, запуск тестирования в тонком клиенте 1С.
3. **ТЗ и Бриф:** просмотр и редактирование `brief.md`, валидация обязательных разделов.
4. **Бюджет и Логи:** визуальный прогресс лимита MCP (25 вызовов), кнопки «+10 вызовов» и «Сбросить лимит», таблица MCP-событий с временем и статусом.
5. **Сдача в 1 клик:** интерактивный чек-лист готовности, автоматическая сборка клиентского ZIP-архива с инструкцией и копированием на Рабочий стол (`~/Desktop/1C_Delivery`).
6. **Гарантия и Git:** фиксация архитектурных решений в `DECISIONS.md`, управление гарантийным периодом 30 дней.

### 5. Финансовая аналитика и Инструменты
- Расчет выручки, чистой маржинальности, реальных затрат на AI (OpenRouter) и эффективной ставки ₽/час.
- Экспорт финансовых отчетов в формате CSV.
- Просмотр и копирование эталонных сниппетов из базы «Золотой фонд 1С».
- Запуск генерации еженедельных уроков и тестов.

### 6. Системный Доктор (10 проверок окружения)
Встроенная диагностика окружения разработчика:
1. Версия Python (>= 3.10)
2. Наличие зависимостей из `requirements.txt`
3. Доступность Git в PATH
4. Доступность исполняемого файла `code` (VS Code)
5. Наличие расширения Roo Code
6. Права на запись в каталог заказов (`C:\Orders`)
7. Валидность файла `config.json`
8. Статус прокси-шлюза Guard (:8766)
9. Статус сервера 1C:EDT MCP (:8765)
10. Обнаружение тонкого клиента 1С:Предприятие (`1cv8c.exe`)

## Guard 2.0: Надежность и безопасность

- **Синтаксический контроль BSL (BSL001-BSL005):** статический анализ парных блоков (`Если/КонецЕсли`, `Попытка/КонецПопытки`, `Цикл`, `Процедура`, `Функция`, `#Область`, `#Если`), блокировка `write_module_source` и `patch_method` при синтаксических ошибках без списания лимита вызовов.
- **Дисковый кэш чтения:** кэширование повторных вызовов `get_metadata_objects`, `get_metadata_details`, `get_module_structure` в `state/cache/<project>/` с выборочной инвалидацией при записи модулей.
- **Компактор ответов:** фильтрация технических GUID/UUID и пустых полей в JSON-ответах EDT, предотвращающая раздувание контекста LLM.
- **Автономия заказа:** маршрутизация по URL `/mcp/{profile}/{order_id}` исключает путаницу с активным заказом.
- **Трекинг затрат:** фиксация токенов и расчет расходов в USD и RUB по курсу конфигурации.
